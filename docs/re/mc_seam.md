# NFSU / Max Payne host-web seam

Research only, 2026-11-09. Problem: draw the running Max Payne build's player inside NFSU Free Run, with one world frame and shared occlusion. No runtime replacement, block code, build, game run or browser run was made.

`N/` means this NFSU worktree; `M/` means `/Users/angeldamian/maxpayne-re` (read-only). Line numbers refer to the source files read here, not generated wasm. NFSU HEAD was `64cc01351faca39b4ae5dd73aed6eaf397e861c0`; Max Payne HEAD was `b28fb1aec1d19e2e6e05efbabbe29d0ade354399`. Max Payne had existing staged changes, including `web/index.html`: its working-tree lines below are not a claim that HEAD contains that page. Pin the imported source separately before an import commit.

**FACT** means established by static source, not observed execution. **INFERENCE** marks a proposed seam or a consequence. **UNKNOWN** means evidence is missing. Every local citation below was read. This document does not close a playable lane row.

1. **Player draw isolation:** which Max draw calls contain the third-person animated player, weapon, skin parts and shadows; how to exclude Max rooms/HUD and how camera visibility/culling affects them. No packet field names the player.
2. **One frame and camera snapshot:** exact Free Run main-view render boundary, target/depth lifetime at that point, correct V/P and near/far for that view, and how to pair a Max pose with that NFSU frame. Existing FXAA marker and size-based scene tracking are candidates, not proof.
3. **Placement and units:** Max room-to-render transform, unit scale, both full signed bases/handedness and NFSU ground-query-to-render mapping. No unsupported Y/Z conversion or common metre scale is asserted. Existing reference `N/docs/re/track.md:36` identifies `0x440a40` as `GroundQuery::FindSurfaceBelow`, not a WebGPU present hook.
4. **Camera API choice:** Max exports no external V/P setter today. A future imported host hook requires rebuilding that imported host; byte-identical wasm requires enough packet-side transform evidence, which is missing. NFSU lighting on Max also needs a light/material bridge; sharing camera/depth alone preserves Max's own lighting.
5. **Runtime/artifact compatibility:** no two-runtime execution, actual combined memory/RSS, pointer-lock/audio/storage behavior, imported file manifest, or match between present source and existing `web/out` wasm was verified. Max's dirty page is explicitly not pinned by HEAD alone.
