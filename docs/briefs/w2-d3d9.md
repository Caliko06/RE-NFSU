# Window 2: D3D9 -> WebGPU, first frame (Opus)
Worktree ~/RE-NFSU-wt/d3d9, branch w-d3d9, web port 5181. Read AGENTS.md and HANDOFF.md first. Window 1 (main) merges.

## Goal
Speed.exe today stops at `d3d9.dll!Direct3DCreate9` (0x40883c). Make the game create its device and present
its first frame: a canvas in Chrome shows what the game draws (a cleared screen is the first gate).

## Facts
- Host functions: `uint32_t f(Ctx *c)`, args with `ARG(n)`, table entries `{dll, name, nargs, fn}` (see host/net.c).
  Register a table in `find_api` (host/dispatch.c). Missing = loud stop, never a silent stub.
- COM objects: allocate the object and its vtable in guest memory (`guest_alloc`). Each vtable slot =
  `host_addr_of("d3d9.dll", "IDirect3DDevice9::Clear")`-style fake address, with nargs that include `this`.
  The game calls them through rn_call like any import.
- Guest calls back: `call_guest` (host/dispatch.c). Threads: one GIL (host/threads.c); never block while holding it.
- The window: CreateWindowExA comes after Direct3DCreate9 (host/user32.c). Present needs the HWND -> canvas.
- Web build: main() runs in a pthread worker (PROXY_TO_PTHREAD). Rendering from a worker needs a plan:
  OffscreenCanvas + WebGPU in that worker plus a way to yield per frame (JSPI or hand-off). Decide and say why.
- Native: render off-screen with `--shot` (no window that takes focus); same D3D9 layer code for both.

## Rules
- Follow the D3D9 documentation, never game behavior. Caps, adapter modes, formats: report one real-looking
  D3D9 HAL device; log every query the game makes (RN_TRACE) so the values can be checked against Wine later.
- Unimplemented methods stop loudly with their name. No game value is tuned.
- Do not touch tools/recomp/ (window 1 is closing M1 there). host/ files of others: only add your table hook.
