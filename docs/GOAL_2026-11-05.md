## 3. Test rule (the only one)
Test only when a change touches one of these:
- boot or menus;
- the render/present path or shaders (gpu.js, sm1.c);
- physics or collision shared with original mode;
- the build;
- deletions.
Each test is one `webcheck --route` or one same-seed ghost or difftest.
A perf change is done only with its number. Everything else: build, ship on :5180, and the OWNER plays. No re-validation. A test below this bar is not run and not counted.

## 7. Top risks
1. Safari's WGSL compiler rejects a generated shader. Mitigation: the Safari smoke run comes first, at hour 1.
   - Evidence it boots: an iPhone ran this page with the same waitAsync pump (HANDOFF 3fba755; a worker's claim). Safari has had Atomics.waitAsync since 16.4 (inference).
2. The perf zero is a tail metric: GC, the OS and heat decide it. Mitigation: bench slots with other windows quiet, reported per cause.
3. LAN: the CA must be trusted once per device, and HTTP/1.0 plus TLS per request may hitch over Wi-Fi. Mitigation: HTTP/1.1 keep-alive and the /setup page.
4. Digital touch steering may feel as late as the keyboard. Analog steering is a later step.
5. Three builds at once strain memory. Mitigation: RN_JOBS=4, macgate, and staggered merges.
