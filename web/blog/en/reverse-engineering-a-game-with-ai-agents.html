Reverse engineering a game with AI agents: what worked

The first commit is from October 19, 2026. Four weeks and 1,022 commits later, the game was public. One person directed the work; AI coding agents did most of the reading, writing and testing.

Updated November 17, 2026

Who did what

  • The owner chose the direction, played every build and said yes or no. A rejected idea was written down and not reopened without them.
  • Claude (Anthropic's Claude Code) planned, read the binary and wrote most of the lifter and the host.
  • Codex (OpenAI) took whole slices in parallel: a subsystem, a tool, a test.
  • OpenCode with DeepSeek handled cheap, wide jobs: search the decompiled code, fill a census table, run a batch.

The risk: a confident guess

A language model can write a plausible offset or a plausible file format that is simply wrong, and a game built on wrong values fails far away from the mistake. Most of the rules of this project exist to stop that.

  • Proof or UNKNOWN. Every value, format or patch names what proves it: an address read with REA (a reverse engineering server agents use over MCP) plus a second tool such as Ghidra or Hopper. Unproven means UNKNOWN, and nothing is built on it. More on that in the toolbox.
  • A machine judge. The lifter's output is compared bit for bit with a reference x86 CPU. An agent cannot argue with a mismatch. See static recompilation.
  • Loud failures. A missing instruction or a missing DirectX method stops the game with its name, so a gap is found the first time it runs instead of hiding.
  • Real runs. Changes are checked in a headless, muted Chrome that boots the real game and takes screenshots, and the owner judges from those screenshots and from playing.
  • One state file. A plan file lists every step with its state (fixed, verified, fails) and the evidence. A new session starts from it, not from memory.

What did not work

Long reports, percent-done scores and big multi-agent ceremonies cost time without making the game better, and were dropped. Heavy testing was cut to one check that matches how the owner plays. What stayed is small: a goal, the evidence rule, a commit after every finished step, and a person who plays the result.

The code and its history are public on GitHub.
